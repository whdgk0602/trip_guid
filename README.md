# 데일리루트 (Daily Route)

> 당신의 평범한 일상 경로를, AI가 매력적인 로컬 여행 콘텐츠로 재구성해주는 서비스.

**Live demo**: https://trip-guid.vercel.app

## 프로젝트 개요

여행 콘텐츠는 대부분 유명 관광지 중심으로 소비됩니다. 하지만 개인의 일상 경로(출퇴근길, 동네 산책로 등)는 그 지역을 모르는 사람에게는 새로운 로컬 경험이 될 잠재력이 있습니다. 데일리루트는 이 경로를 한 문장으로 입력받아 주변 장소를 큐레이션하고 스토리텔링해서, SNS에 공유할 수 있는 매력적인 "로컬 가이드 콘텐츠"로 재구성해주는 서비스입니다.

- **왜 만들었나**: 풀스택 개발 역량(프론트/백엔드/AI 연동/배포)과 프리미엄 모델을 포함한 제품 기획력을 증명하기 위한 포트폴리오 프로젝트입니다.
- **차별점**: 유명 관광지가 아니라 "누군가의 일상"을 여행 콘텐츠로 재해석한다는 프레이밍
- **기술 스택**: Next.js 16 (App Router, Route Handlers, TypeScript) · Tailwind CSS v4 · Vitest · Vercel
- **외부 서비스**: 카카오 로컬 API(지오코딩·장소 검색) · OpenRouter 무료 LLM · Upstash Redis(갤러리 저장소)

## 어떻게 작동하나요

1. **경로 입력** — 랜딩 화면(`/`)에서 일상 경로를 한 문장(10~300자)으로 적어 제출합니다.
2. **생성** — `/generate` 로딩 화면(3단계 스테퍼)이 보이는 동안 `POST /api/routes/generate`가 실제 데이터로 코스를 만듭니다.
   1. **지명 추출** — LLM이 문장에서 지명을 뽑습니다 ("대림역에서 2호선 갈아타고 강남역" → `["대림역", "강남역"]`).
   2. **지오코딩** — 카카오 키워드/주소 검색으로 좌표를 얻습니다. 같은 이름이 여러 곳이면 직전 경로 지점에서 가장 가까운 후보를 고르고, 30km 넘게 튀는 결과는 버립니다.
   3. **장소 큐레이션** — 경로 지점 주변의 카페·식당·공원·볼거리·문화시설을 카카오에서 찾아, 카테고리가 겹치지 않고 경로에 고르게 퍼지도록 무료 3곳/프리미엄 5곳을 고릅니다. 부족하면 반경을 500m → 1km → 2km로 넓힙니다.
   4. **코스 텍스트** — LLM이 코스 제목·소개·스팟 설명을 씁니다. 주어진 정보(이름·카테고리·주소) 밖의 사실(메뉴, 가격, 영업시간 등)은 쓰지 않도록 제한하고, 응답을 검증합니다.
3. **결과 확인** — 코스 제목·소개와 스팟별 카드(이름/카테고리/설명)가 렌더링됩니다.
4. **저장 또는 공유** — "저장하기"로 공개/비공개를 선택해 저장하거나, "공유하기"로 코스를 PNG 이미지 카드로 내보냅니다. 공개로 저장한 코스는 서버 갤러리에 게시됩니다.
5. **다시 찾아보기** — `/my`(내 코스)에서 저장한 코스를 필터링하고 공개/비공개를 바꾸며, `/gallery`에서 모든 사용자가 공개한 코스를 최신순으로 둘러봅니다.
6. **등급 전환** — `/plan`에서 무료/프리미엄 기능 차이를 비교하고, 가짜 구매 플로우를 거쳐 등급을 전환해볼 수 있습니다.
7. **체크인 & 여행기** (프리미엄) — `/my/[id]`에서 코스의 각 스팟에 체크인 기록을 남기고, 모든 스팟을 완료하면 그 기록을 엮은 여행기를 생성합니다.

이 모든 과정에서 **회원가입/로그인은 없습니다.** 브라우저가 처음 방문 시 스스로 발급한 `anonymousId`(로컬 저장소에 보관되는 UUID)로 사용자를 식별합니다.

## 주요 기능

| 화면 | 기능 |
|---|---|
| **랜딩 · 경로 입력** (`/`) | 일상 경로를 한 문장으로 입력. 10자 미만/300자 초과 시 제출 차단 및 에러 메시지 표시 |
| **생성 중 로딩** (`/generate`) | "경로에서 장소 읽기 → 주변 장소 찾기 → 코스 만들기" 3단계 스테퍼. 실패 시 원인별 안내 — 장소를 못 읽음/위치를 못 찾음/주변 장소 없음은 입력 예시와 함께 재입력, 외부 API 장애는 재시도 버튼 |
| **결과 화면** | 코스 제목/소개, 스팟 카드 목록(번호·이름·카테고리·설명). 주변 장소가 요청 개수보다 적으면 안내 표시 |
| **저장 · 공개 설정** | 공개(갤러리 게시)/비공개(이 브라우저에만) 선택. 브라우저 데이터 유실 시의 영향 안내 포함 |
| **공유 카드** | 코스를 카드 이미지 미리보기로 보여주고 PNG로 다운로드. 무료 등급은 워터마크 포함, 프리미엄은 워터마크 제외 |
| **내 코스** (`/my`) | 저장한 코스를 전체/공개/비공개로 필터링. 공개/비공개 전환 시 갤러리에 게시·삭제, 방문 시 공개 코스 재동기화 |
| **갤러리** (`/gallery`) | 모든 사용자가 공개한 코스를 서버에서 불러와 최신순 노출(최근 50개). 가장 최근 코스는 Editor's pick 형태로 강조 |
| **등급 비교 · 결제** (`/plan`) | 무료/프리미엄 기능 차이(스팟 개수, 워터마크, 체크인·여행기 여부) 비교. "프리미엄 구매하기" → 가짜 결제 화면 → 완료 순으로 등급 전환. 데모 편의를 위한 "무료로 되돌리기" 포함 |
| **체크인 + 여행기** (`/my/[id]`, 프리미엄 전용) | 스팟마다 한 줄 기록(+사진 미리보기)을 남기고, 모든 스팟을 완료하면 기록을 엮은 여행기를 생성. 무료 등급에는 잠금 UI만 표시 |

각 화면의 완료 조건·엣지 케이스는 [`docs/slices/`](./docs/slices)에 기능별로 정리돼 있습니다 (Phase 0 당시 스펙. Phase 1 변경 사항은 [`PLAN.md`](./PLAN.md) 참고).

## 설계 포인트

- **무료 LLM 위에서 안정적으로 동작하기** — OpenRouter 무료 모델은 계정 단위 일일 한도(429), 수십 초 지연, 빈 응답이 잦습니다. 그래서
  - 모델 폴백을 직접 순회하고(모델별 요청 옵션, 추론 필수 모델은 토큰 한도를 올려 재시도), 단계별 **시간 예산**(지명 추출 8초·코스 텍스트 10초)을 넘으면 중단합니다.
  - LLM을 쓸 수 없으면 지명은 **규칙 기반 추출기**(역/동/공원/길… 접미사 + 조사 제거)로, 코스 텍스트는 **템플릿**으로 대체해 생성 자체는 실패하지 않습니다.
  - 성공한 LLM 결과는 Next.js `unstable_cache`로 30일간 재사용합니다 (같은 문장·같은 스팟 조합).
- **갤러리 위조 방지** — 생성 API가 코스 내용에 HMAC 서명을 붙이고, 게시 API는 서명을 검증합니다. 서버가 만든 코스만 공개 갤러리에 올라갑니다.
- **로그인 없는 소유권** — 갤러리에는 `sha256(anonymousId)`만 저장해, 같은 브라우저만 자기 코스를 비공개로 돌릴 수 있습니다. 목록 응답에는 소유자 정보가 없습니다.
- **테스트 가능한 서버 코드** — Route Handler는 외부 호출(LLM·카카오·Redis)을 주입받는 handler와 실제 연결만 하는 `route.ts`로 나눠, 외부 서비스 없이 단위 테스트합니다.

## 서비스에 필요한 추가 설명

- **비공개 코스와 등급은 이 브라우저에만 저장됩니다.** 브라우저 데이터를 지우거나 다른 기기로 접속하면 접근할 수 없습니다. 공개 코스는 서버 갤러리에 남지만, `anonymousId`를 잃으면 더 이상 비공개로 돌릴 수 없습니다 (각 화면에 안내).
- **AI 문구는 무료 모델 상황에 따라 템플릿으로 바뀔 수 있습니다.** 일일 한도가 소진되면 "OO에서 OO까지" 형태의 기본 문구가 나옵니다. 장소 큐레이션(카카오)은 영향을 받지 않습니다.
- **프리미엄 결제는 실제로 이루어지지 않습니다.** "프리미엄 구매하기"는 등급 전환 UX를 시연하기 위한 가짜 결제 플로우입니다. `/plan`의 "무료로 되돌리기"는 데모 편의 기능입니다.
- **체크인 사진은 저장되지 않습니다**(새로고침 시 사라짐). 여행기는 체크인 기록을 바탕으로 AI가 쓰며, AI를 쓸 수 없을 때는 기록을 엮은 기본 여행기를 보여주고 다시 시도할 수 있습니다.
- **공유 카드 이미지 저장이 드물게 실패할 수 있습니다.** `html-to-image` 기반 PNG 변환이 간헐적으로 멈추는 알려진 이슈가 있어, 8초 타임아웃 후 재시도할 수 있게 처리했습니다.

## 시작하기

```bash
npm install
cp .env.example .env.local   # 값 채우기 (아래 표)
npm run dev
```

| 환경변수 | 용도 | 없으면 |
|---|---|---|
| `KAKAO_REST_API_KEY` | 카카오 로컬 API (지오코딩·장소 검색) | 코스 생성 불가 |
| `OPENROUTER_API_KEY` | 지명 추출·코스 텍스트 LLM | 규칙 기반 추출 + 템플릿 문구로 동작 (로컬에서 무료 한도를 아끼려면 비워두기) |
| `OPENROUTER_MODEL` | 시도할 모델 목록(쉼표 구분, 앞에서부터) | 필수 (키가 있을 때) |
| `GALLERY_SIGNING_SECRET` | 코스 서명·게시 검증 | 갤러리 게시 불가 |
| `KV_REST_API_URL`, `KV_REST_API_TOKEN` | Upstash Redis (Vercel 연동 시 자동 주입) | 개발 서버에서만 메모리 저장소로 대체, 운영은 오류 |

```bash
npm test        # vitest — 서버 로직(src/lib/server)·클라이언트 로직(src/lib) 단위 테스트
npm run lint
npm run build
```

## 프로젝트 구조

```
src/
├─ app/
│  ├─ page.tsx                   # 랜딩 · 경로 입력 (/)
│  ├─ generate/                  # 로딩 → 결과, 에러 화면, 저장·공유 모달
│  ├─ my/                        # /my 내 코스, /my/[id] 상세 · 체크인 · 여행기
│  ├─ gallery/page.tsx           # 서버 갤러리 (최신순)
│  ├─ plan/page.tsx              # 등급 비교 · 가짜 결제 플로우
│  └─ api/
│     ├─ routes/generate/        # POST 코스 생성 (handler.ts 로직 / route.ts 연결)
│     ├─ gallery/                # GET 목록, PUT·DELETE /[id] 게시·삭제
     └─ travelogue/             # POST 체크인 여행기
└─ lib/
   ├─ anonymousId.ts · savedRoutes.ts · tier.ts · checkins.ts   # 브라우저 저장소 로직
   ├─ galleryClient.ts           # 갤러리 게시·삭제·동기화 클라이언트
   └─ server/
      ├─ llm.ts                  # OpenRouter 호출, 모델 폴백·시간 예산
      ├─ extractPlaceNames.ts    # LLM 지명 추출 (+ 규칙 기반 폴백 연결)
      ├─ ruleBasedPlaceNames.ts  # LLM 없이 지명 추출
      ├─ kakao.ts                # 지오코딩, 주변 장소 검색
      ├─ resolveRoutePlaces.ts   # 지명 → 경로 좌표 (근접 보정·이탈 제거)
      ├─ curateSpots.ts · buildCourse.ts   # 스팟 선정, 반경 확대
      ├─ courseText.ts           # 코스 제목·소개·설명 생성 + 검증 + 템플릿 폴백
      ├─ travelogue.ts           # 체크인 기록 → AI 여행기
      ├─ courseSignature.ts      # HMAC 서명/검증
      └─ gallery.ts · galleryStore.ts      # 게시 규칙, Upstash REST 저장소

docs/
├─ concept.md · feature-spec.md · prd.md · business-model.md
└─ slices/                       # 기능별 구현 스펙 (Phase 0)
```

기획/설계 문서는 항상 `docs/*.md`가 원본(source of truth)이며, 프로젝트 전체 규칙은 [`CLAUDE.md`](./CLAUDE.md), 세션별 실행 계획은 [`PLAN.md`](./PLAN.md)를 참고하세요.
