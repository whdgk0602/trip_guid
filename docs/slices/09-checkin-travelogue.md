# 기능 9 (스트레치): 프리미엄 사용자가 저장한 코스를 걸으며 스팟별로 체크인을 남기고, 완주 후 AI 여행기를 받을 수 있다

> PRD FR-11/FR-12 (P2) · feature-spec.md 2.7/4장. 코드 없음, 스펙만.

## 완료 조건

- [ ] `/my`에서 저장한 코스를 클릭하면 코스 상세 화면(`/my/[id]`)으로 이동한다 (지금은 `/my`가 목록만 보여주고 상세로 들어가는 진입점이 없음)
- [ ] 상세 화면에는 코스의 스팟 목록이 보이고, 각 스팟마다 체크인 여부(완료/미완료)가 표시된다
- [ ] 등급이 프리미엄이면 각 스팟에서 "체크인" 버튼을 눌러 한 줄 기록(텍스트)과 사진 1장을 남길 수 있다
- [ ] 등급이 무료면 체크인 영역이 잠금 UI(예: "프리미엄 전용" 안내 + `/plan`으로 가는 링크)로 표시되고 기록을 남길 수 없다
- [ ] 모든 스팟에 체크인을 남기면 "완주"로 간주되어 "여행기 생성" 버튼이 활성화된다 (그 전에는 비활성 + "n/총 스팟 수 체크인 완료" 안내)
- [ ] "여행기 생성"을 누르면 체크인 기록(텍스트)들을 조합한 개인화 여행기 문단이 화면에 보인다
- [ ] 한 번 생성된 여행기는 저장되어, 상세 화면을 다시 방문해도 계속 보인다

## 안 되는 경우

- 무료 등급 사용자가 체크인을 시도 — 잠금 UI만 보이고 입력 자체가 불가능 (버튼/입력창 없음)
- 스팟 일부만 체크인한 상태에서 "여행기 생성" — 버튼이 비활성 상태라 클릭 자체가 안 됨

## 이번에 안 하는 것

- **실제 AI/LLM 연동** — 지금 프로젝트에는 실제 LLM 호출이 없음(mock 데이터 기반, `docs/prd.md` Phase 0 범위). 이번에도 실제 LLM을 부르지 않고, 체크인 기록을 조합하는 **결정론적 템플릿 함수**로 여행기를 만든다 (감정/키워드 반영은 스트레치 이후 실제 LLM 연동 시점으로 미룸)
- 사진 실제 업로드/저장(서버·클라우드 스토리지) — 사진은 브라우저 로컬에서만 다루고, 새로고침해도 남아있을 필요는 없음(아래 "물어볼 것" 참고)
- 체크인 기록 수정/삭제
- 코스 재방문(같은 코스 두 번째 완주) 시나리오
- MVP_DESIGN 비주얼 디자인 — 다음 디자인 적용 라운드

## 확인 방법

1. `npm run dev` 실행
2. 무료 등급 상태에서 코스 저장 → `/my`에서 코스 클릭 → 상세 화면에서 체크인이 잠금 UI로 보이는지 확인
3. `/plan`에서 프리미엄 전환 → 같은 코스 상세 화면에서 체크인 가능한지 확인
4. 스팟마다 한 줄 기록 + 사진을 넣어 체크인 → 마지막 스팟 체크인 전까지 "여행기 생성" 버튼이 비활성인지 확인
5. 모든 스팟 체크인 후 "여행기 생성" 클릭 → 여행기 문단이 보이는지 확인
6. 새로고침 후에도 체크인 텍스트 기록과 여행기가 유지되는지 확인 (사진은 세션 전용이라 새로고침하면 사라지는 게 정상)
7. 자동화 테스트: `checkins.ts`의 `isRouteComplete`, `buildTravelogue` 등 순수 함수 테스트(vitest). 화면 흐름은 수동 확인
