# 기능 3: 사용자가 결과 화면에서 코스 제목/소개와 스팟 3개를 모바일 폭에서도 깨지지 않게 볼 수 있다

> PRD FR-4(목업 렌더링) · PLAN.md "오늘 만들 기능" 3번. 코드 없음, 스펙만.

## 완료 조건

- [ ] mock 데이터의 코스 제목과 소개가 결과 화면 상단에 표시된다
- [ ] 스팟 3개가 각각 이름/카테고리/설명을 담은 카드 형태 블록으로 구분되어 표시된다
- [ ] 360px 폭(모바일 기준)에서 가로 스크롤이나 텍스트 잘림 없이 레이아웃이 유지된다

## 안 되는 경우

- 스팟 설명이 길 때 → 카드 밖으로 넘치지 않고 줄바꿈되어 카드 안에 표시된다

## 이번에 안 하는 것

- 실제 비주얼 디자인(색상 팔레트, 타이포그래피, 브랜딩, 그림자 등) — 지난 대화에서 이 단계는 디자인 없이 진행하기로 확인함. 카드 구분을 위한 최소 구조적 스타일(여백, 테두리, 줄바꿈 방지)만 적용
- 로딩 화면(문구 전환) 로직 변경 — 02 슬라이스에서 이미 구현, 이번엔 그대로 둠
- 저장하기 · 공유하기 · 다시 만들기 액션 버튼 — `feature-spec.md` 2.3에 있지만 PLAN.md 기능 3 범위 밖 (다음 슬라이스)
- 등급별 스팟 개수 차등(프리미엄 5개) — 게이팅은 이후 슬라이스, 이번엔 3개 고정 유지
- `GenerateClient.tsx`를 여러 컴포넌트로 분리하는 것 — 01·02 슬라이스와 같은 방침으로 한 파일에 계속 유지

## 건드릴 파일

- **고칠 파일**: `src/app/generate/GenerateClient.tsx` — `course`가 있을 때 렌더링하는 부분에 Tailwind 유틸리티 클래스(세로 스택 레이아웃, 스팟별 카드 블록의 여백·테두리·줄바꿈 처리)만 추가. 로딩 문구를 보여주는 분기는 손대지 않음

## 확인 방법

1. `npm run dev` 실행
2. `/`에서 10~300자 텍스트를 제출 → 결과 화면에서 제목/소개가 상단에, 스팟 3개가 구분된 카드 블록으로 보이는지 확인
3. 브라우저 개발자도구에서 뷰포트를 360px로 좁혀 가로 스크롤이나 텍스트 잘림이 없는지 확인
4. 자동화 테스트는 없음 — 완료조건이 전부 시각적 확인 대상이라 계산/판단 로직이 없음. 컴포넌트 렌더링을 자동 테스트하려면 `jsdom`+`@testing-library/react` 설치가 필요한데, 새 라이브러리 설치는 사전 협의 대상이라 이번엔 수동(브라우저) 확인으로 진행
