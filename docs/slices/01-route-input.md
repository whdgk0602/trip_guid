# 기능 1: 사용자가 경로를 입력하고 제출할 수 있다

> PRD FR-1 · PLAN.md "오늘 만들 기능" 1번. 코드 없음, 스펙만.

## 완료 조건

- [x] 10~300자로 경로를 입력하고 제출하면 `/generate?text=...`로 이동한다
- [x] 이동 직후 잠깐 로딩 화면(`loading.tsx`)이 보였다가, 입력했던 텍스트가 화면에 그대로 표시된다

## 안 되는 경우

- 입력이 10자 미만이거나 300자를 초과할 때 → 제출이 막히고 에러 메시지가 표시된다 (PLAN.md 완료조건 원문)

## 이번에 안 하는 것

- 실제 AI 생성(FR-2~4), 목업 API 호출 — 다음 슬라이스. `/generate` 화면은 이번엔 입력받은 텍스트를 그대로 보여주기만 함
- 로딩 화면의 세부 UX(단계별 상태 텍스트 "주변 장소 찾는 중" 등) — 다음 슬라이스. 이번엔 `loading.tsx`가 잠깐 보이는 정도만 확인
- 코스 저장(FR-5) — 생성 "결과"가 나온 뒤에 하는 일. 지금 루트 화면의 "저장 → localStorage" 로직은 이 작업으로 없어짐
- `src/lib/types.ts`, `src/components/` 등 폴더 구조 미리 만들기

## 건드릴 파일

- **고칠 파일**: `src/app/page.tsx` — "저장" 버튼/`localStorage` 로직을 제거하고, 글자 수 검증(10~300자) + 제출 시 `/generate?text=입력값`으로 이동하는 로직으로 교체
- **새로 만들 파일**:
  - `src/app/generate/page.tsx` — 쿼리스트링의 `text`를 받아 그대로 화면에 표시 (실제 생성 없음)
  - `src/app/generate/loading.tsx` — `/generate`로 이동할 때 자동으로 보이는 로딩 화면. `loading.tsx`가 실제로 보이려면 `generate/page.tsx`가 잠깐 대기하는 인위적 지연이 필요해서, 아주 짧은(1초 정도) 인위적 지연을 하나 넣음 (실제 생성 로직이 아니라 로딩 화면 동작 확인용)

## 확인 방법

1. `npm run dev` 실행
2. `/`에서 9자 이하 텍스트를 입력해 제출 → 막히고 에러 메시지가 뜨는지 확인
3. `/`에서 10~300자 텍스트를 입력해 제출 → `/generate?text=...`로 이동하며 로딩 화면이 잠깐 보이는지, 이후 입력했던 텍스트가 그대로 표시되는지 확인
4. 자동화 테스트는 아직 없음 (수동 클릭 확인만)
